    02 - Windows Server Setup

    Goal

    In this lesson, you will install and prepare Windows Server 2022 for the hospital identity environment.

    Later, this server will become the Domain Controller responsible for services such as:

    • Active Directory Domain Services
    • DNS
    • user authentication
    • identity management
    • group-based access control

    At this stage, we are only preparing the operating system.

    Before You Start

    You should already have:

    • a virtualisation platform installed
    • a Windows Server virtual machine
    • a Windows Server 2022 installation ISO attached to the VM
    • sufficient CPU, memory, and disk resources allocated

    If you have not created the VM yet, complete the Virtualisation Setup lesson first.

    Step 1 - Start the Windows Server VM

    Start the virtual machine containing the Windows Server ISO.

    The VM should boot into the Windows Server installation environment.

    Select your:

    • language
    • time and currency format
    • keyboard layout

    Then continue to the installation screen.

    Step 2 - Choose the Windows Server Edition

    Depending on the installation media, several editions may appear.

    For a beginner-friendly environment, choose a version that includes:

    Desktop Experience

    For example:

    Windows Server 2022 Standard Evaluation
(Desktop Experience)

    Desktop Experience vs Server Core

    Desktop Experience provides the familiar Windows graphical interface.

    Server Core provides a minimal installation without the traditional desktop interface and is normally administered primarily through command-line tools and remote management.

    For this project, Desktop Experience makes it easier to explore tools such as:

    • Server Manager
    • Active Directory Users and Computers
    • DNS Manager
    • Computer Management

    Step 3 - Choose the Installation Type

    When Windows asks which type of installation you want, choose:

    Custom: Install Microsoft Server Operating System only

    A custom installation is appropriate because we are creating a new server rather than upgrading an existing Windows installation.

    Step 4 - Select the Virtual Disk

    Windows will display the virtual disk created for the VM.

    Select the available unallocated disk space and continue.

    For this learning environment, a virtual disk of approximately 40-60 GB is normally sufficient.

    Windows will automatically create the partitions required for the operating system.

    Step 5 - Complete the Installation

    Windows Server will copy files and install the operating system.

    The virtual machine may restart several times.

    After installation, you will be asked to configure the built-in:

    Administrator

    account.

    Create a strong password that you can remember for the lab.

    Warning

    Do not reuse real passwords from personal, university, or workplace accounts.

    This project should use credentials created specifically for the simulated environment.

    Step 6 - Sign In

    After installation is complete, sign in using the Administrator account.

    You should reach the Windows Server desktop.

    Server Manager will normally open automatically.

    Server Manager is one of the main administration tools used to configure Windows Server roles and features.

    Step 7 - Inspect the Server

    Before changing anything, inspect the current system.

    Open:

    Server Manager → Local Server

    Look for information such as:

    • computer name
    • Windows edition
    • network adapter
    • IP address
    • time zone
    • Windows Firewall status
    • remote management status

    The objective is to understand the server's current state before configuring it.

    Step 8 - Check the Computer Name

    Every computer on a network needs a hostname.

    You can check the current hostname from Command Prompt:

    hostname

    You can also use PowerShell:

    $env:COMPUTERNAME

    The default hostname generated by Windows may not be very meaningful.

    Later, you may rename the server to something easier to recognise, such as:

    DC01

    This naming convention can help identify the machine as the first Domain Controller in the environment.

    Step 9 - Inspect the Network Configuration

    Open Command Prompt and run:

    ipconfig

    Look for:

    • IPv4 Address
    • Subnet Mask
    • Default Gateway
    • DNS Servers

    Do not worry if the address was automatically assigned.

    In the next lesson, we will examine how IP addressing, DNS, DHCP and virtual networking affect communication between the Windows Server and Ubuntu machines.

    Step 10 - Check Internet Connectivity

    If your virtualisation network provides internet access, test connectivity.

    For example:

    ping 8.8.8.8

    You can also test DNS resolution:

    nslookup microsoft.com

    These tests answer two different questions.

    ping 8.8.8.8 helps test basic IP connectivity.

    nslookup microsoft.com helps verify that DNS name resolution is working.

    Optional - Create a Snapshot

    Once Windows Server is installed and working, consider creating a virtual machine snapshot.

    A useful snapshot name could be:

    Windows Server Clean Install

    This gives you a recovery point before making major configuration changes.

    What You Should Understand

    Before continuing, make sure you can explain:

    Why are we using Windows Server instead of normal Windows?

    Windows Server provides enterprise services such as Active Directory Domain Services, DNS, centralized authentication, and server roles.

    What is Server Manager?

    Server Manager is an administration interface used to configure and monitor Windows Server.

    Why do we inspect the network before configuring Active Directory?

    Active Directory depends heavily on reliable networking and DNS.

    If network configuration is incorrect, authentication and directory services may fail later.

    Why are we not configuring Active Directory yet?

    We are separating the project into layers.

    First we establish the server.

    Then we configure networking.

    After networking is understood and verified, we add the identity services.

    Checkpoint

    Before moving on, confirm that:

    • Windows Server boots successfully
    • you can sign in as Administrator
    • Server Manager opens
    • the server has a hostname
    • the server has an IP address
    • you can inspect its network configuration
    • the virtual network adapter is working

    Challenge

    Using only the tools available inside Windows Server, find:

    1. your hostname
    2. your IPv4 address
    3. your default gateway
    4. your DNS server
    5. your Windows Server edition

    Try to explain what each value represents rather than simply copying it.
